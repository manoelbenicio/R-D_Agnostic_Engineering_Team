## Migration/query contract

The `up` placeholder will add nullable `idempotency_key TEXT` to
`daemon_token`, then create a unique partial index on
`(workspace_id, daemon_id, idempotency_key)` where the key is not null. The
`down` must drop that exact index and column only. Existing rows and overlap
tokens remain valid.

Queries to add/update:

- create accepts `idempotency_key`;
- lookup by `(workspace_id, daemon_id, idempotency_key)` returns token metadata
  only;
- single-token revoke remains bound by id/workspace/daemon;
- expired purge remains unchanged.

The handler requires a non-empty bounded `Idempotency-Key` header, uses strict
JSON decoding, and performs the lookup before minting. A retry with the same
key returns a deterministic `409 already issued` metadata response and does
not mint a second row or expose the prior raw token. A first successful issue
returns the raw token exactly once with `Cache-Control: no-store`; failures
never print it. This is the approved equivalent retry contract: no orphan or
duplicate can be created, while raw-token replay remains impossible by design.
