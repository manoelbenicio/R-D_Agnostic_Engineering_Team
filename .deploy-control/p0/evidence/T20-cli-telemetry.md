# Route hop omni_request_id — RESOLVED by official docs (provisional blocker withdrawn) 2026-07-23T23:08Z
## Resolution (per Principal + Anthropic official docs)
Claude Code 2.1.214+ (installed 2.1.218) emits `claude_code.api_request` via OTLP logs with `request_id` (from API response `request-id` header) and `client_request_id` (x-client-request-id). Supports OTLP http/json. This is the REAL per-inference ID — no proxy, no OmniRoute internals. Ref: https://docs.anthropic.com/en/docs/claude-code/monitoring-usage
## Verified mechanism gap (why a naive smoke emitted nothing)
Live smoke with CLAUDE_CODE_ENABLE_TELEMETRY=1 + OTEL_LOGS_EXPORTER=console set in the DAEMON launcher produced NO telemetry: the daemon builds a TRUSTED/allowlisted child env (internal/daemon/runtimeenv/policy.go — explicit DenyClaudeMarker for CLAUDE_CODE_* + CLAUDECODE_/CLAUDE_CODE_USE_ prefix denials), so operator-set telemetry/OTEL vars are STRIPPED from the child claude process. => telemetry must be DAEMON-INJECTED as trusted child env, not operator passthrough (matches Principal's 'trusted child env' instruction).
