## 3. `codex app-server` — exact wiring

### 3a. Protocol and config-file approach (recommended)

Codex reads its provider configuration from `$CODEX_HOME/config.toml`.
The controlled task home must contain **only** the OmniRoute provider block; no `auth.json`; no
copied upstream provider definitions.

**`$CODEX_HOME/config.toml` — full content to generate:**

```toml
# Generated by operator for ORQ1 -> OmniRoute wiring.
# Do NOT add any other [model_providers.*] block.
# Do NOT add base OpenAI credentials or auth.json.

[model_providers.omniroute]
name        = "OmniRoute"
base_url    = "http://100.118.244.61:20128/v1"
wire_api    = "responses"
env_key     = "CODEX_OMNIROUTE_API_KEY"
```

`wire_api = "responses"` instructs Codex to use the OpenAI Responses API (HTTP/SSE), which OmniRoute
exposes at `/v1/chat/completions` in compatible mode.

### 3b. Environment variables

```bash
# Isolation: remove any inherited raw OpenAI/Codex credential paths
unset OPENAI_API_KEY
unset OPENAI_API_KEYS
unset OPENAI_BASE_URL
unset CODEX_API_KEY

# Gateway wiring
export CODEX_HOME="/path/to/controlled/codex-home"        # must contain only the config.toml above
export CODEX_OMNIROUTE_API_KEY="$OMNIROUTE_API_KEY"       # loaded at runtime via secret mechanism; NEVER hardcoded

# Correlation (optional but recommended for tracing)
export X_SESSION_ID="<multica-session-id>"
export X_REQUEST_ID="<multica-request-id>"
```

### 3c. Launch command

For GLM/ClinePass slot (CP-1 / CP-2):

```bash
codex app-server \
  --model "cp/cline-pass/glm-5.2" \
  --provider omniroute
```

For OpenAI Codex slot (OC-1 / OC-2):

```bash
codex app-server \
  --model "openai/gpt-4.1" \
  --provider omniroute
```

> **NOTE**: The `--model` value must exactly match the model ID registered in the OmniRoute catalog
> (`GET /v1/models` returns the authoritative list). Use `cp/cline-pass/glm-5.2` for the
> primary GLM slot and `nvidia/z-ai/glm-5.2` as fallback.

## 4. `cline --acp` — exact wiring

### 4a. Protocol

Cline in ACP (Agent Completion Protocol) mode reads provider configuration from
`$CLINE_DATA_DIR/settings/providers.json`. The controlled `providers.json` must reference the
OmniRoute endpoint, not any raw provider URL.

### 4b. `providers.json` — content to generate

```json
{
  "providers": [
    {
      "id": "omniroute",
      "name": "OmniRoute",
      "type": "openai",
      "baseUrl": "http://100.118.244.61:20128/v1",
      "apiKey": "<RUNTIME_RESOLVED_KEY>",
      "models": [
        "cp/cline-pass/glm-5.2",
        "nvidia/z-ai/glm-5.2"
      ],
      "defaultModel": "cp/cline-pass/glm-5.2"
    }
  ],
  "activeProvider": "omniroute"
}
```

`apiKey` must be set to the runtime-resolved key value. The `<RUNTIME_RESOLVED_KEY>` placeholder
above indicates the field must be populated via the secret mechanism before writing the file to disk;
the literal placeholder string must never appear in the running file.

### 4c. Environment variables

```bash
# Isolation: remove any inherited Cline/provider credential paths
unset OPENAI_API_KEY
unset ANTHROPIC_API_KEY
unset ANTHROPIC_AUTH_TOKEN
unset ANTHROPIC_BASE_URL

# Cline data dir — must point to controlled directory containing the providers.json above
export CLINE_DATA_DIR="/opt/multica/runtime/cline-data-dir"

# Gateway key for Cline slot (ClinePass accounts CP-1 ... CP-4)
export CLINE_OMNIROUTE_API_KEY="$OMNIROUTE_API_KEY"   # loaded at runtime; NEVER hardcoded

# Correlation
export MULTICA_SESSION_ID="<multica-session-id>"
export MULTICA_REQUEST_ID="<multica-request-id>"
export MULTICA_ROUTER_OWNER="omniroute"
```

### 4d. Launch command

```bash
cline --acp
```

ACP mode: Cline listens on stdin/stdout for JSON-RPC messages from the Multica daemon.
The daemon injects the task; Cline uses the configured `providers.json` provider to route through
OmniRoute.

## 5. `kiro-cli` — exact wiring

### 5a. Protocol

Kiro-cli uses the Anthropic Messages API shape by default (internally maps to
`/v1/messages`). OmniRoute exposes a compatible endpoint. The controlled wiring is through
`ANTHROPIC_BASE_URL` pointing at OmniRoute root (no `/v1` suffix — Kiro appends `/v1/messages`
itself) and `ANTHROPIC_AUTH_TOKEN` set to the OmniRoute-issued key.

> **IMPORTANT**: Kiro-cli historically used a SQLite credential store at
> `$XDG_DATA_HOME/kiro-cli/data.sqlite3`. In gateway-required mode this native store must
> **not** be exposed. Use a clean controlled `XDG_DATA_HOME` that contains no Kiro native auth,
> and provide credentials exclusively via environment variables as shown below.

### 5b. Environment variables

```bash
# Isolation: remove any inherited Kiro/Anthropic credential paths
unset ANTHROPIC_API_KEY
unset ANTHROPIC_AUTH_TOKEN   # will be re-added as trusted value below
unset KIRO_API_KEY
unset XDG_DATA_HOME           # will be re-set to controlled clean home

# Gateway wiring for Kiro (Anthropic Messages API via OmniRoute)
export ANTHROPIC_BASE_URL="http://100.118.244.61:20128"   # no trailing /v1 — Kiro appends it
export ANTHROPIC_AUTH_TOKEN="$OMNIROUTE_API_KEY"           # OmniRoute key, NOT raw Anthropic key; NEVER hardcoded

# Clean credential discovery root — prevents native SQLite store exposure
export XDG_DATA_HOME="/opt/multica/runtime/kiro-clean-xdg"  # must be an empty/controlled dir
export HOME="/opt/multica/runtime/kiro-clean-home"           # controlled clean home

# Model to target (Anthropic Messages compatible model on OmniRoute)
export KIRO_MODEL="claude_code_kimi_2.7_Code"   # as declared in READINESS-routes.md

# Correlation
export MULTICA_SESSION_ID="<multica-session-id>"
export MULTICA_REQUEST_ID="<multica-request-id>"
export MULTICA_ROUTER_OWNER="omniroute"
```

### 5c. Launch command

```bash
kiro-cli \
  --model "claude_code_kimi_2.7_Code"
```

If `kiro-cli` supports a `--base-url` flag (verify against installed version on ORQ1):

```bash

  --base-url "http://100.118.244.61:20128" \
  --model "claude_code_kimi_2.7_Code"
```

The env-var form (`ANTHROPIC_BASE_URL`) is authoritative; the flag form is additive if supported.

## 6. Validation commands (read-only smoke-test after operator wires)

These are safe read-only probes that the operator can run **after** wiring, without requiring
inference credits:

```bash
# 6.1 Confirm gateway liveness (no auth required)
curl -s -o /dev/null -w "%{http_code}" http://100.118.244.61:20128/status
# Expected: 200

# 6.2 Confirm model catalog is reachable (requires API key in header)
curl -s \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  http://100.118.244.61:20128/v1/models \
  | python3 -c "import sys,json; d=json.load(sys.stdin); print(f'models={len(d[\"data\"])}')"
# Expected: models=327

# 6.3 Confirm target models present in catalog
curl -s \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  http://100.118.244.61:20128/v1/models \
  | python3 -c "
import sys, json
d = json.load(sys.stdin)
ids = {m['id'] for m in d['data']}
targets = ['cp/cline-pass/glm-5.2', 'nvidia/z-ai/glm-5.2', 'claude_code_kimi_2.7_Code']
for t in targets:
    print(f'{t}: {\"PRESENT\" if t in ids else \"ABSENT\"}')
"
```
